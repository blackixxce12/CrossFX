# CrossFX 1.0 on Windows: the porting matrix

CrossFX 1.0 runs on Linux and on Windows 10 and 11 (64-bit). The window, the presets, the
equalizer, the effects, the voice chain, the translations and the command line are one body of code
on both. What differs is what sits under them: PipeWire, D-Bus, StatusNotifierItem and the
compositor on Linux; WASAPI, a named pipe, the notification area and toasts on Windows. This
document lists each Linux feature and what it is in CrossFX for Windows 1.0:

- **Same** — the same code does the same thing.
- **Different** — it is there, and works another way; the table says how.
- **Not in 1.0** — Windows 1.0 does not have it. Two kinds: what has no Windows meaning (it is
  PipeWire's, or D-Bus's), and what a later version may add. This document gives no dates for
  either.

It was written from the code (`crates/crossfx-audio/src/wasapi/`, `crates/crossfx-app/src/win/`,
`crates/crossfx-core/src/platform.rs`) and from the README. Where a row says "same", it means the code
is shared; the Windows-specific parts are tested in CI as far as a CI machine with no sound card
allows, and a check that changes the default device and plays the system's sound through CrossFX is
run by hand (`cargo test -p crossfx-audio --lib wasapi::live::end_to_end_on_this_machine --
--ignored`), never in CI.

## The scope of 1.0

On Windows, CrossFX processes sound through **a virtual playback device that the user already
has**: VB-Audio's VB-CABLE (or another virtual cable), or the "FxSound Speakers" device of the
original FxSound's driver. CrossFX ships no driver and installs none. It is VB-CABLE's licence that
keeps it from being bundled: VB-CABLE is donationware that the user installs, and CrossFX only
links to VB-Audio's own page, <https://vb-audio.com/Cable/>, from a button in the window
("Get VB-CABLE…") that is shown when no virtual cable is found (the original FxSound's driver is
no cable: the microphone lane cannot use it).

These are **not in 1.0**, and nothing in CrossFX promises them:

| Not in 1.0 | What it would be |
|---|---|
| The APO engine mode | Processing the sound on the real speakers as a Windows system effect, with no virtual device in the path |
| A bundled FxSound driver | Shipping the original FxSound's "FxSound Speakers" driver with CrossFX |
| The audio-mode selector | A selector of how CrossFX reaches the sound, with four entries; 1.0 has the one way described here |
| Per-application presets on Windows | A preset of its own for each application, as on Linux (below) |

## The matrix

### Audio and processing

| Feature | Linux | Windows 1.0 | State |
|---|---|---|---|
| The music chain: equalizer, fidelity, ambience, surround, dynamic boost, bass, limiter | the lane's DSP | the lane's DSP, unchanged (`crate::lane_dsp`) | Same |
| Where the sound comes from | CrossFX publishes a PipeWire sink, `CrossFX (Output)`; applications play into it | a virtual playback device that is already installed (VB-CABLE, another cable, or "FxSound Speakers"); CrossFX makes it the default of the playback roles and captures it with WASAPI loopback | Different; needs the device |
| Where it goes | the real output device chosen in CrossFX | the same, by WASAPI shared-mode render | Same |
| Defaults handed back | the previous default is remembered and given back on the way out, before the nodes are destroyed | each role's previous default is remembered and given back before the streams stop: on Exit, at the end of the Windows session, with the power off; a record under `%LOCALAPPDATA%\CrossFX` lets the next start put back what a killed run left | Same idea, different mechanism |
| A cable CrossFX does not use | n/a | offered like any other device; a default Windows put on a cable by itself (a cable just installed, a device that went away) is Windows' doing and is put back where it was; a default the user put there stays theirs | Windows only |
| The microphone lane: voice chain (denoise, high-pass, expander, equalizer, de-esser, compressor, limiter) | a virtual source, `CrossFX (Input)` | the same chain, written to the playback side of a second virtual cable; applications record from its recording side. With no second cable the lane reports it and processes nothing | Different; needs a second cable |
| The microphone is opened only while something records | yes | yes: the recorders on the cable are heard through their sessions | Same |
| RNNoise noise suppression | built in | built in | Same |
| Echo cancellation | PipeWire's WebRTC canceller | none; the control is not shown | Not in 1.0 |
| Per-application presets and routes (Settings ▸ Applications, `--app-preset`, `--list-apps`) | each application's stream is moved onto a node of its own | the tab is not shown; the options are accepted but nothing is routed, every application plays on the lane's preset | Not in 1.0 |
| Smooth moves in WirePlumber, Restart WirePlumber | an optional WirePlumber script fades a stream moved to another device | not shown; Windows moves streams itself | Not in 1.0 (no Windows counterpart) |
| The lane's volume | the volume of `CrossFX (Output)`, kept per output device and applied after the chain | the virtual device's volume | Different |
| The original FxSound runs | n/a | the output lane stands aside (takes no default, processes nothing) and says why; CrossFX never reads or changes the original's files, settings or driver | Windows only |
| Device rules: priority list, "Follow the system's default device", a preset remembered per device | the same | the same code | Same |
| Sleep and resume | logind's `PrepareForSleep` | `PowerRegisterSuspendResumeNotification`; both lanes mute on the way down and start clean on the way up | Different mechanism, same behaviour |

### Window, tray and notifications

| Feature | Linux | Windows 1.0 | State |
|---|---|---|---|
| The window, its views, Settings, dialogs | egui, native on Wayland | egui | Same |
| Typeface | Manrope; a Gilroy the user bought can be imported | the same; a Gilroy installed in `%LOCALAPPDATA%\Microsoft\Windows\Fonts` or `%WINDIR%\Fonts`, or added in Settings, is found | Same (Gilroy is never shipped) |
| Interface language | the session's `LC_ALL`, `LC_MESSAGES` or `LANG`, or the language switch / `--language` | the first language in the user's preferred-languages list that CrossFX has a table for (Windows' own rule for applications), or the language switch / `--language` | Different |
| Tray | StatusNotifierItem (`ksni`) | an icon in the notification area, with the same menu, states and tooltip; drawn for the DPI of the taskbar's monitor and again when the scale changes; the light taskbar gets a near-black icon | Different mechanism, same behaviour |
| Notifications | `org.freedesktop.Notifications` | a toast (one slot, silent), registered under CrossFX's AppUserModelID; removed when CrossFX quits | Different mechanism, same behaviour |
| Opening links and folders | `xdg-open` | `ShellExecuteW`, for `http` and `https` links and existing folders only | Different |
| Preset import and export | the system's file dialogs (XDG portal) | the system's file dialogs | Same |
| "Like the original FxSound LLC" (Experimental) and its three levels | yes | the same | Same |
| Launch on system startup | `~/.config/autostart/io.github.blackixxce12.CrossFX.desktop` | the value `CrossFX` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; Task Manager's Startup tab turning it off is read back | Different |
| Where files live | `~/.config/crossfx`, `~/.local/share/crossfx` | `%APPDATA%\CrossFX` (`settings.toml`, `apps.toml`, `presets`, `fonts`) and `%LOCALAPPDATA%\CrossFX` | Different |
| Ending with the session | `SIGTERM`, `SIGINT`, `SIGHUP` | console control events and `WM_QUERYENDSESSION`/`WM_ENDSESSION`; the defaults are handed back (waiting at most four seconds) | Different mechanism, same behaviour |

### Command line, scripting and packages

| Feature | Linux | Windows 1.0 | State |
|---|---|---|---|
| Every option of `crossfx` | yes | yes, from `crossfx.exe`; a release build is a program with a window, so it borrows the terminal it was started from to print what a command has to say | Same |
| Single instance and the channel to the running one | `$XDG_RUNTIME_DIR/crossfx/instance.sock` | the named pipe `\\.\pipe\crossfx-<user SID>`, for this user only | Different mechanism, same protocol |
| `--status --json`, `--watch` | yes | yes, over the pipe | Same |
| `--self-test` | PipeWire and the session bus, no sound | the audio service and the playback endpoints, no sound | Different |
| D-Bus interface (`io.github.blackixxce12.CrossFX`) | methods, properties and signals | none; the pipe carries every command | Not in 1.0 (no Windows counterpart) |
| Global shortcuts | compositor keybindings that run `--toggle-power`, `--next-preset`, `--prev-preset`, `--next-output`, `--toggle-window`; Hyprland example | the same commands exist for any tool that binds a key (a shortcut's Shortcut key, PowerToys, AutoHotkey); CrossFX registers no hotkey itself | Different |
| Packages | `.deb`, Fedora `.rpm`, Arch and AUR, tarball | setup program (Inno Setup), `.msi` (WiX 7), portable `.zip`, each with a SHA-256 sum | Different |
| Licence notices | in every package | in every package: RNNoise, Noto, Manrope and egui's built-in fonts | Same |

## What the user does on Windows

1. Installs a virtual playback device: VB-CABLE from VB-Audio's page (the **Get VB-CABLE…** button
   opens it), or has the original FxSound's driver. A second cable is needed for the microphone
   lane.
2. Closes the original FxSound if it runs; CrossFX processes while it is closed.
3. Starts CrossFX. It makes the virtual device the default, and plays the result on the speakers
   chosen in its window; quitting hands the default back.
